# RoonController

A web-based remote control and now-playing display for the Roon music system. Designed for always-on screens (Raspberry Pi with touchscreen, wall-mounted tablets, iPads in kiosk mode).

## Architecture

```
Browser (frontend/)  <--WebSocket-->  Node.js (backend/)  <--Roon API-->  Roon Core
```

- **Backend**: Express HTTP server + WebSocket server. Connects to Roon Core via auto-discovery, subscribes to zone events, relays state to browser clients.
- **Frontend**: Vanilla HTML/CSS/JS single-page app. No build tools, no frameworks.

## Project Structure

```
backend/
  server.js          # Express + WebSocket server, routes, client message handling
  roon-handler.js    # Roon API integration, zone state management, client-zone mapping
frontend/
  index.html         # UI markup
  styles.css         # Dark iOS-inspired theme, responsive layout, away mode styles
  app.js             # WebSocket client, UI updates, inactivity tracking
config.json          # Auto-generated by Roon API. Stores pairing token + client zone preferences
```

## Key Concepts

### Client Identification
Each browser client gets a persistent ID (`client_<timestamp>_<random>` via localStorage, or `client_<name>` via `?client=name` URL param). This ID maps the client to a Roon zone and persists across reconnections.

### Per-Client Zone Assignment
Each client independently selects which Roon zone to control. Preferences are stored server-side in `config.json` via `roon.save_config()`. On reconnect, the server restores the client's previous zone.

### WebSocket Protocol
Messages are JSON with `{ type, payload/data }`.

**Client → Server:**
- `identify` — `{ clientId }` — must be first message
- `control` — `{ command: 'play'|'pause'|'playpause'|'stop'|'previous'|'next' }`
- `volume` — `{ mode: 'absolute', value: <number> }`
- `mute` — `{ action: 'mute'|'unmute' }`
- `select_zone` — `{ zoneId }`
- `seek` — `{ seconds: <number> }` (absolute)

**Server → Client:**
- `init` — full state on connect
- `update` — state change for client's zone
- `zones` — full zone list (broadcast to all clients)

### State Shape (server → client)
```js
{
  connected: boolean,
  zone: { zone_id, display_name } | null,
  nowPlaying: { title, artist, album, image_key, length, seek_position } | null,
  state: 'playing' | 'paused' | 'loading' | 'stopped',
  controls: { is_play_allowed, is_pause_allowed, is_previous_allowed, is_next_allowed, is_seek_allowed },
  volume: { value, min, max, step, is_muted, type } | null
}
```

### Away Mode
After 5 seconds of no user input, the UI enters "away mode": hides controls, enlarges text for viewing from across the room. Any interaction exits it. If volume changes while in away mode (e.g. from a hardware remote), a large overlay appears briefly showing the new level.

### Album Artwork
Served via `GET /api/image/:imageKey?width=800&height=800`. The backend proxies this through `RoonApiImage.get_image()`. Images are cached by the browser (1 hour).

## Running

```bash
npm start              # Start server on port 3000
PORT=8080 npm start    # Custom port
```

### macOS LaunchAgent
A LaunchAgent is installed at `~/Library/LaunchAgents/com.timcornelissen.rooncontroller.plist` for auto-start on login. Restart after code changes:
```bash
launchctl kickstart -k gui/$(id -u)/com.timcornelissen.rooncontroller
```

Logs: `~/Library/Logs/rooncontroller.log` (rotated by newsyslog at 1MB, 3 backups).

## Common Patterns

### Adding a new command from frontend to Roon
1. Add handler function in `app.js` that calls `sendCommand(type, payload)`
2. Add case in `handleClientMessage()` in `server.js`
3. Add method in `roon-handler.js` that calls the appropriate `this.transport.*` method

### Zone lifecycle
Zones can appear and disappear at any time (Roon restart, output power, network issues). The code must handle:
- `subscribe_zones` returning 0 zones initially (Roon still discovering)
- `zones_added` arriving later as outputs come online
- `zones_removed` when outputs go offline (preferences are kept, not reassigned)
- Client's preferred zone not existing yet (getState returns null zone gracefully)
